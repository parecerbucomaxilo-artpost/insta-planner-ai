# Architecture rules
- AI model options, defaults, legacy validation and provider routing live in src/lib/ai-models.ts; only catalog-verified stable IDs are offered, explicit legacy choices are preserved or rejected without substitution, and generation failures never return local simulated content.
- Anthropic is explicitly unconnected; its former browser-key UI removes the obsolete localStorage entry without reading it, because the project has no native Claude generation path.
- Generated-post review uses the shared PostReviewActions component and existing posts statuses through the authenticated browser client, so RLS applies and internal approval never invokes publishing.
- Keep review actions before long slide/caption content and expose saved pending posts through visible navigation; generation refreshes persisted lists without auto-scheduling.
- Parent previews remain mounted after internal review so the shared modal can display the saved decision; calendars expose undated pending posts separately instead of filtering them away.
- The shared review modal fetches saved media and platform captions by post ID; slide text is matched by its explicit slide number, and inline caption edits use a status-guarded browser update without publishing.
- Chico images use finalized slide text through the contextual-image pipeline; generation errors never substitute providers or procedural images, so unrelated imagery cannot be saved as success.
- Assign the post ID before image generation and bind fresh storage objects to slide indexes; validate order, completeness and unique URLs before inserting the post to prevent cross-post or cross-slide reuse.- Post dedup lives in src/lib/dedup.ts and runs inside generateSinglePost (history of last 60 days, batch check, posts.content_key unique per user) so every planner is covered; duplicates raise visible errors, never silent saves.
- Default posting slots come only from src/lib/post-slots.ts and are resolved in the project/user time zone (never the server's); batch generation runs sequentially with an operation+slot idempotency key so retries and double clicks cannot insert a second post per slot.
- Semantic dedup maps each topic to a root subject (ASSUNTOS_RAIZ in src/lib/dedup.ts): same subject is allowed again only with a different explicit angle and not on the same day; without angles the JANELA_ASSUNTO_DIAS window applies; text conflicts get at most 2 rewrites then a visible error — wording-only checks missed same-subject posts, while subject-only blocking emptied the calendar.
- Preview loads by post ID via loadPostPreview (src/lib/post-preview.ts) with strict per-slide signing; failures show inside the modal, never a fallback public URL (buckets are private).
- New posts from any creation path (AI generator or manual save) go through src/lib/post-guard.ts (shared history, semantic dedup, content_key idempotency); never insert into posts directly from a component.
- Approval requires an opened preview: PostReviewActions and ApproveAllReview gate on podeAprovar (src/lib/post-review.ts); media/text problems need explicit ignore, batch duplicates are never approvable.
- Carousel slide count comes only from quantidadeSlides (src/lib/carousel-slides.ts); preview/approval flag Instagram feed carousels off the default and block repeated slides.
- Fixed-schedule topics come from distribuirTemas/planDistinctTopics: distinct root subjects first, then an editorial matrix (subject x angle, never a repeated pair from batch or history) fills every slot; a remaining shortfall shows a "Gerar novos temas" action, never silent copies.
- Posts 7 dias runs through src/lib/week-run.ts (executarSemana): one click plans and generates every slot, state persists in localStorage for resume, retries reuse operacaoId+slotKey, and image failures save text with salvarTextoSeImagemFalhar so a slot is never reported complete without media.
- Topic originality is enforced server-side in generateSinglePost via reformularTema (src/lib/dedup.ts): conflicting topics get a new angle, then a new subject, each revalidated with a finite limit, so no path asks the user to fix topics manually.
- Global image realism directive lives in src/lib/image-realism.ts and is appended inside generateImageBase64 so every image path (single, cover, carousel slide, backfill) gets it; it never carries palettes, which stay per-brand in brand-book.ts.
- Generated posts auto-open the shared review modal via PostReviewActions autoOpen (latest finished post in batch flows); auto-preview only marks the preview as seen, never approves, schedules or publishes.
- Text language rule lives in src/lib/plain-language.ts and is appended to every caption system prompt; plain language for the general public, technical level kept only for estudantes-graduacao or linkedin-cientifico.
